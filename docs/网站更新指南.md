以后只需把照片放进指定文件夹，然后把下面任一段复制给 Codex，并补上知道的信息。不知道的留空；不需要自己改网页或 JSON。

## 1. 新增观鸟活动

照片放入 `incoming/events/`，每次活动可以建子文件夹。

> 请新增观鸟活动。日期：；地点：；路线：；组织者：；主要鸟种（我已确认）：；参加人数：；活动介绍：；总结：；照片文件夹：。请整理英文草稿，未知信息留空，用开发分支生成预览，未经确认不要正式发布。

数据模板：`content/templates/event.json`。由 Codex 将完整条目添加至 `content/events.json`。照片数组格式为 `[{"image":"incoming/events/文件.jpg","alt":"准确的英文图片说明"}]`。活动按日期从新到旧展示；缺少日期的排在最后。

## 审核与发布

Codex 会把新增内容加入对应栏目；只有填写真实 `updatedAt` 日期的已公开条目进入首页 Latest Updates。旧内容迁移不虚构更新日期，因此初始 Latest Updates 显示提示语。

检查英文、日期、鸟名、照片版权和购买链接。确认无误后明确说“批准将这个预览版本发布到正式网站”。此前只在开发分支和预览中工作。

技术维护：Node 24 LTS，首次运行 `npm ci`，之后 `npm run build` → `npm run check` → `npm run preview`，打开 http://127.0.0.1:4173。修改数据后重新构建即可。Vercel 沿用 `npm run build` 和 `dist`，自动安装 sharp 图片处理依赖。原照片仅供本机预处理，incoming 已被 Git 忽略，不上传 GitHub 或 Vercel。Codex 先运行 `npm run prepare-content`（`npm run build` 会自动先运行），生成去 EXIF、最长边 1600 的网页图至 `assets/uploads/`，自动更新数据引用，再将网页图和数据文件一起提交。Vercel 取得这些已提交的网页图后，生成 480/1600 展示版本到 dist 并部署。dist 无需进入 GitHub；不能只提交数据而漏掉 assets/uploads。旧 assets 中原有的已跟踪图片保留，本规则适用于以后放入 incoming 的照片。

若启用 GitHub 自动预览，开发分支推送后在 Vercel 项目 Deployments 中打开对应 Preview；不要点击 Promote to Production。未核实 Vercel Production Branch 前不要盲目推送。

## 以后每次更新

1. 你只需在当前项目放入照片，并发中文指令。
2. Codex 同步远端、处理图片、整理英文与数据，运行检查，提交数据及网页图到开发分支，提供对应 Vercel Preview。原图继续留在本机，请自行备份。
3. 你审核并明确批准后，Codex 才将审核过的版本合入 main，验证正式部署。首次发布会包含本次基础升级；以后每次仍先检查 main 是否有其他更新。

此流程需要 GitHub SSH 与 Vercel 连接仍可用。它由 Codex 执行，不是放照片后自动发布；不需要你手动编写代码或上传优化图片。
